# n8n_project

A practice engagement for becoming a professional n8n builder: **Northgate Voice Desk**, a voice receptionist for a fictional physiotherapy clinic, built with n8n Cloud, ElevenLabs and OpenAI.

The brief, the seven missions and their acceptance criteria are in [`northgate-voice-desk.html`](northgate-voice-desk.html). Open it in a browser.

## What's built so far

| Mission | Folder | What it adds |
|---|---|---|
| 1 · Harden the voice loop | [`mission1/`](mission1) | Record → n8n → speech-to-text → reply → text-to-speech. Input validation, request log, recorder page |
| 2 · Give it a brain | [`mission2/`](mission2) | AI agent with memory per conversation, clinic FAQ, book/check/cancel tools, emergency guardrail before the AI |
| 3 · Fail well | [`mission3/`](mission3) | Retries, timeouts, text and spoken fallbacks, staff alerts via Pushover, replay protection |
| 6 · Real-time agent | [`mission6/`](mission6) | Booking tools as webhooks for an ElevenLabs voice agent; race-safe booking |
| Side project · BalanceBeam | [samsonadmasu/balancebeam](https://github.com/samsonadmasu/balancebeam) (own repo) | Form → AI agent rebalances an equity portfolio in Google Sheets using Marketstack prices, then sends Gmail + Pushover |

## How the pieces fit

```
Recorder page / ElevenLabs agent
        │
        ▼
Northgate · Voice Loop  ──(tools)──►  Northgate · Agent tools  ──►  northgate_bookings (data table)
        │                                     │
        └──────── failures & crashes ─────────┴──►  Northgate · Staff alerts  ──►  Pushover + northgate_alerts
```

- Workflows are generated by small Python builders (`build-*.py`) from the Code-node sources next to them, so every change shows up as a readable diff.
- Each mission has an acceptance test script (`test-*.sh`) that runs against the live webhooks.

## Running the tests

```bash
cp mission1/.env.example mission1/.env   # then fill in the values
./mission1/test-mission1.sh
./mission2/test-mission2.sh
./mission3/test-mission3.sh
./mission6/test-agent-tools.sh
```

`.env` is git-ignored. No API keys or credentials are stored in this repo. The workflows reference n8n credentials by id only, and the Pushover user key is replaced with a placeholder.
